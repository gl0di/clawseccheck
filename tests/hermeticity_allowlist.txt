# Hermeticity ledger allowlist -- read by tests/test_hermeticity_gate.py.
#
# READ-shaped paths only. A WRITE-shaped event outside the repo/tmp/interpreter-root
# categories is ALWAYS a hard FAIL, in both `CSC_HERMETICITY_LEDGER=1` and `=strict` --
# no allowlist, no grandfathering (there is no legitimate reason for a hermetic test to
# write anywhere else). This file only ever widens what an otherwise-unexplained READ
# may touch, and even then only turns into a hard FAIL under `=strict`; a plain `=1` run
# just reports a diff for local investigation.
#
# One fnmatch-style glob pattern per line ('*' matches any run of characters, including
# '/' -- fnmatch has no path-segment concept, so 'x/**' and 'x/*' match the same set;
# both spellings appear below purely to say what is meant). '$HOME' is a literal token,
# substituted at comparison time for whichever real path this ledger line's recorded
# $HOME actually was (the ledger's own child, or -- when that path is independent of
# $HOME entirely, e.g. resolved via $PATH -- this machine's real home). NEVER write a
# raw '/home/<user>/...' path here; test_allowlist_file_parses_and_is_nonempty() fails
# the build if one leaks in.

# ---- genuinely universal (observed on every real run, not machine-specific) --------
#
# Both the bare directory AND its "/**" contents are listed for every directory below --
# an fnmatch '*' matches zero-or-more characters but NOT the literal '/' the "/**" form
# requires, so a listdir/scandir/stat of the BARE directory (raw path "/proc", no
# trailing slash) does not match "/proc/**" on its own. Missing this the first time
# around is exactly the kind of gap this ledger exists to catch -- see the "found the
# actual surface is wider" note on the host-detect entry below, which is what surfaced
# it (test_no_unexplained_paths_outside_tmp_and_repo initially failed on bare "/proc"
# and bare "/etc/cron.d" et al even with the "/**" entries already present).
/proc
/proc/**
/proc/*/fd
/proc/*/fd/**
/dev/null
# /dev/urandom: CPython's os.urandom()/secrets/uuid fall back to reading this device
# directly on some platforms and interpreter versions rather than the getrandom(2)
# syscall -- observed empirically on the Python 3.9 floor (uv run --python 3.9) but not
# on the 3.12 system interpreter on this same box, confirming this really is
# interpreter-version-dependent and not something to special-case for 3.9 alone.
/dev/urandom
/dev/random

# ---- known, diagnosed violations, each dated and pointed at what removes it --------

# CLAWSECCHECK-hermeticity, 2026-09-21. Any CLI end-to-end test that spawns a real
# `python -m clawseccheck` subprocess without `--no-deptree` (e.g.
# tests/test_b582_viewer_chain_provenance.py) walks the REAL machine's global npm
# install: deptree.find_package_root() resolves `openclaw` via shutil.which()/$PATH,
# which is independent of $HOME -- including when the test overrides $HOME for an
# unrelated reason (isolating OpenClaw config), so the walked path is this machine's
# real home, not whatever fake $HOME that subprocess was given. Measured on the box
# this ledger was built on: 578MB / 37,220 files under the real package root, 6,717
# distinct paths touched by test_b582_viewer_chain_provenance.py alone.
# conftest.py's `_stub_deptree_scan` fixture only patches the IN-PROCESS
# `clawseccheck._deptree_scan` and cannot reach a separate subprocess -- which is the
# reason this ledger exists at all: a parent-only audit hook recorded ZERO hits from
# the same run this caught 6,717 of. The real fix (an env-var child-stub propagated the
# same way this ledger propagates its own env vars, so a spawned child can force
# `_deptree_scan`/`_host_detect` off) is scoped to branch perf/test-subprocess-deptree,
# not this change. This entry is what keeps a strict run from failing on a violation
# that is diagnosed and already has a fix in flight, instead of either silently
# omitting it or blocking every PR until that branch lands.
$HOME/.npm-global/**

# CLAWSECCHECK-hermeticity, 2026-09-21. Sibling of the entry above, same shape, found
# while building this ledger and NOT previously documented: `_stub_host_detect` also
# only patches the in-process `clawseccheck._host_detect` and does not cross into a
# subprocess, so the same CLI end-to-end tests make real, absolute-path host-posture
# reads (the /proc/<pid>/fd reads from the same probe are already covered by the
# /proc/** entries above). First run of this ledger against
# tests/test_b582_viewer_chain_provenance.py found the actual surface is wider than
# cron alone -- systemd unit dirs and the firewall (ufw/nftables) config this box
# happens to have -- so the entries below are what was EMPIRICALLY OBSERVED on one real
# run, not a guess at hostpersist.py's probe list; a future run surfacing a path not
# listed here means the probe grew, not that this entry was wrong. Unlike the deptree
# entry, no fix branch exists yet for this one -- it has not been filed as its own
# follow-up bug at the time this ledger was written, only recommended as one. Listed
# here rather than left for a strict run to discover cold, so the next person to turn
# strict mode on sees a named, reasoned violation and not a mystery.
